# 导出所有笔记

记事本列表页工具栏的「导出所有笔记」放在「新建文件夹」前。点击后将全部已保存的云端笔记打包成 ZIP，与当前文件夹筛选无关；本机未保存草稿不包含在内。

## 文件与格式

压缩包名为 `皮皮2047_所有笔记_YYYY-MM-DD_HH-mm-ss.zip`（本地时间）。每条笔记是压缩包根目录中的独立文件：纯文本为 `.txt`，Markdown 为 `.md`，使用 UTF-8 编码，正文保留原文。

文件名使用笔记标题，替换路径和文件系统不支持的字符，限制为 50 个 Unicode 字符；空标题使用「无标题」。同名文件自动追加 ` (2)`、` (3)`，按大小写不敏感判断；Windows 保留名称加 `_` 前缀。分类记录在文件内容中，不建立分类子目录或导出 JSON。

正文后空一行，接一条 `---` 分隔线和三行附加信息。纯文本：

```text
---
分类：工作
添加于：2026-10-01 09:02:03 +08:00
最后编辑：2026-10-04 09:02:03 +08:00
```

Markdown 是列表，值放在行内代码里：

```markdown
---
- 分类：`工作`
- 添加于：`2026-10-01 09:02:03 +08:00`
- 最后编辑：`2026-10-04 09:02:03 +08:00`
```

分隔线前一定有空行（否则 Markdown 会把正文最后一行当成标题）。分类名按字面显示，名字里有反引号时改用更长的一串反引号包住。时间使用导出时浏览器的本地时区并附 UTC 偏移；未归档笔记写「未归档」。没有笔记时下载有效的空 ZIP，空文件夹不生成文件。

## 下载单条笔记

笔记查看页底部的「下载笔记」在「复制全文」之前，公开页（`/n/<公开 id>`）正文下面也有同一个按钮。点击直接下载这一条的 `.txt` / `.md`，不打包 ZIP，**内容就是原文，不附加分隔线和分类、时间**（尾部信息只在打包导出里有）。文件名规则和打包导出相同。内容取自页面已经读到的那份，不再请求云端；公开页不需要登录。公开页的「下载笔记」后面还有「复制链接」，复制的是 `/n/<公开 id>` 的完整网址（不带查询参数和 hash）。

文件名和下载的实现（`noteFileName()` / `downloadBlob()` / `downloadNote()`）在两个页面共用的 `public/note-render.js` 里。

## 实现与维护

`public/notes.js` 复用现有鉴权接口：先 `GET /api/notes` 读取最新索引，再以每批最多 4 个请求读取 `GET /api/notes/:id`。单请求超时 30 秒；读取失败、响应格式异常、登录状态变化或打包失败时，提示错误且不下载部分文件。导出期间按钮禁用，完成后恢复，下载后释放 Blob URL。

ZIP 使用 [JSZip](https://stuk.github.io/jszip/documentation/api_jszip/generate_async.html) 3.10.2 的 DEFLATE 压缩。锁定开发依赖版本，选择 MIT 许可，`scripts/build-zip-vendor.js` 将官方浏览器产物及许可证复制到 `public/vendor/jszip.min.js`，仅 `notes.html` 加载。`npm run build:zip` 可单独重新生成；`npm run build` 自动生成后复制到 `dist/vendor`。没有新增后端接口。

索引和正文分开读取，不是数据库事务快照；另一个设备同时删除笔记时会提示失败，可完成修改后重试。ZIP 是普通未加密文件；本次提供导出，不新增导入功能。

## 验证

运行 `npm ci`、`npm run test:frontend`、`npm run build`、`npm audit --audit-level=high` 和 `git diff --check`。`test/notes-export.node.cjs` 使用实际 vendor 库生成并解压 ZIP（检查 CRC），覆盖完整原文与元信息、格式后缀、中文及同名文件、路径字符、分类名里的反引号、空 ZIP、并发限制、失败恢复和会话变化。浏览器下载后再使用标准 ZIP 工具核对每个文件的正文和尾部信息。
